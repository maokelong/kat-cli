# KAT PACK PR 固定检查表

本表用于 `kat-pack-review` 的每次检视。逐项保留编号并标记：

- **已核查**：已取得足够材料并完成对应核查；它不表示没有问题，发现的问题另写 finding。
- **不适用**：PR 不涉及该合同或场景，并说明原因。
- **无法验证**：缺少必要材料、环境或可信判据，并说明缺口及其影响。

finding 还必须满足主 Skill 的证据、影响和 PR 归因门槛。检查时以当前集合随附的[框架作者 API](../../kat-author/references/base-api.md)和[PACK 创作流程](../../kat-author/references/pack-authoring-flow.md)为公开合同来源；不要从框架或 SDK 私有源码发明额外约束。

## 1. PR 范围与基线

- **1.1 完整变更面**：确认 PR 基线、当前提交、完整 diff、变更后的相关文件和 PACK 根目录；片段材料必须标为无法覆盖完整 PR。
- **1.2 PACK 归属**：区分 PACK 交付内容、测试/fixture、生成物和无关仓库改动；确认每个候选问题确实属于待审 PACK。
- **1.3 PR 归因**：确认问题由本 PR 新增、扩大，或新代码真实依赖；纯历史问题不列为 finding。
- **1.4 可用证据**：记录已核对的 PR 描述、测试、当前提交 CI、复现结果和权威参考；reviewer 结论不算证据。
- **1.5 审查边界**：不要求 Issue、SDD、验收标准或版本匹配；不评价 PACK 的业务价值。

## 2. PACK 边界与静态结构

- **2.1 Manifest 与根目录**：`pack.toml` 位于 PACK 根并使用受支持字段；名称、标题、描述和 owner 与交付内容一致，没有把动态代码塞进静态发现阶段。
- **2.2 固定目录职责**：Workflow、PACK 自有 Provider、helpers、knowledge 和 tests 位于各自公开位置，入口没有依赖偶然工作目录或仓库外文件。
- **2.3 私有命名空间**：PACK 内 Python 导入遵守自身命名空间；不同 PACK 不通过 `kat.pack` 互相导入 helpers，也不导入框架下划线私有模块。
- **2.4 能力复用边界**：新增实现没有复制已明确存在且满足需求的框架或 SDK 公共能力；若材料不足以证明可复用性则标记无法验证，不凭相似命名报错。
- **2.5 交付闭包**：声明引用的模块、Guide、fixture 和运行时资源随 PACK 一起提供，路径大小写和相对关系在目标平台可成立。

## 3. Workflow 合同

- **3.1 声明与入口**：Workflow 是模块顶层同步函数，声明名称和描述可区分用途；首参为 `ctx: kat.Context`，公开参数具有受支持的精确标注、说明和一致默认值。
- **3.2 输入处理**：Workflow 只接收声明输入，不把秘密设计为可能进入日志的普通参数，不依赖隐式 Session identity、Session 根或未公开环境状态。
- **3.3 输出类型**：返回 `None`、精确 `dp.Table` 或非空 `dict[str, dp.Table]`；不返回 PyArrow Table、Catalog、惰性值、空映射、子类或混合值。输出名稳定且能被 Guide/测试解释。
- **3.4 Context 生命周期**：`datasource_root` 只保存同一 Session 可复用的完整来源物化，`scratch_root` 只放候选执行中间文件；父入口返回前等待自己启动的所有工作并传播错误。
- **3.5 `ctx.run()` 组合**：PACK/Workflow 名称和输入与目标公开合同一致；只传严格匹配的普通值，不把 Table/Catalog 作为输入，也不把子 Catalog 直接作为父输出。
- **3.6 子结果使用**：只在子 Run 完整发布后使用 Catalog，按实际 relation 名查询；无输出子 Run、失败传播、重试和部分成功语义没有被误判。
- **3.7 结果语义**：过滤范围、单位、时钟域、聚合口径、空值和空结果处理与代码、声明、Guide、测试一致；只有具备权威判据时才判断领域算法正确性。

## 4. Datasource / Provider

- **4.1 Provider 选择**：需要来源能力时，材料能证明作者核对了适用公共 Provider 或说明了具体缺口；纯实现偏好不作为 finding。
- **4.2 Import safety**：PACK `datasources/` 导入只定义类和纯元数据，不在 import 时连接服务、读取凭据、解析输入、启动进程、写文件或执行查询。
- **4.3 凭据与配置**：凭据不作为 Workflow 普通输入、不写入代码、fixture、日志、Guide 或输出；来源配置有明确边界，错误不会泄露秘密。
- **4.4 来源身份与路径**：来源参数、stem 和目标路径经过公开合同要求的拒绝与规范化；不扫描目录猜来源，不允许穿越、设备名或大小写冲突绕过所有权边界。
- **4.5 物化复用**：共享物化只发布完整结果；目标已存在时先按 relation、完整 Schema 和稳定版本事实验证后复用，不以目录存在或近似 Schema 当作兼容。
- **4.6 写入与并发**：使用公开 `dp.write()` 等能力，避免覆盖既有结果、暴露半成品或在并发执行下把不同来源合并；失败清理不会删除其他执行拥有的数据。
- **4.7 查询与资源**：SQL relation/参数绑定明确，外部连接、文件、临时数据库、进程和线程在成功与失败路径都能关闭；Provider 中间 Table/Catalog 不被误当成 Run Output。

## 5. Workflow / Provider 知识

- **5.1 声明关联**：声明指向 `knowledge/` 内存在、非空、有效 UTF-8 的普通 Markdown；路径不绝对、不穿越且与 Workflow/Provider 对应。
- **5.2 可发现描述**：名称和 description 足以与相邻能力区分，参数说明让调用者能准备合法输入，没有用实现细节代替用途。
- **5.3 Workflow Guide**：说明自身输出的字段语义、单位、范围、空值/空结果、关键限制、足够作结论的条件和必要的下一步证据，不引导读取私有文件或 Provider 中间状态。
- **5.4 组合 Guide**：父 Guide 只解释父 Run，引用真实 child Run 关系并说明子证据如何支持汇总；不冒充、拼接或覆盖子 Workflow 的独立 Guide。
- **5.5 Provider Guide**：说明数据源、接入、可用 SQL/表/Schema、解析或物化方式及来源语义，不把 Provider Guide 写成分析结论模板。
- **5.6 实现一致性**：知识中的字段、relation、口径和限制与代码、声明及测试一致；无法由现有材料核对的领域含义标为无法验证。

## 6. 测试与可验证证据

本节衡量证据覆盖度，不建立测试门禁。缺少测试、CI、规格、权威参考或 golden data 时标记“无法验证”并写入整体风险；不能只因“潜在错误可能未被测试发现”形成 finding。只有公开交付合同明确要求相应产物却确实缺失，或其他证据已经证明实现行为违反合同，才报告 finding。

- **6.1 生产入口**：Workflow 行为通过 KAT 提供的生产测试接口或等价公开边界验证，而不是只直接调用内部函数绕过 Runtime 合同。
- **6.2 核心路径**：测试覆盖主要成功路径和本 PR 改变的行为，断言公开 Outputs、声明或 Provider 结果，而不只断言“没有异常”。
- **6.3 边界与失败**：按变更风险覆盖空输入/空结果、非法类型与路径、来源失败、资源清理、子 Run 失败、并发或物化复用；不适用时说明原因。
- **6.4 Fixture 可信度**：fixture 小而可解释，不含秘密或个人数据；golden data 有明确来源和预期，不把 mock 行为当成生产保证。
- **6.5 证据对应当前提交**：测试报告、CI 和复现来自正在审查的提交，命令、环境与结果可追溯；跳过、xfail 或只跑局部集合没有被描述成完整覆盖。
- **6.6 领域正确性判据**：只有领域规格、权威实现对照或 golden data 存在时才核对算法正确性；缺失时明确无法验证的结论范围。

## 7. 宿主风险与实现缺陷

- **7.1 导入与初始化副作用**：除 Provider inspection 的 import-safe 要求外，普通模块初始化也不应执行不可逆写入、网络访问、进程启动或环境修改。
- **7.2 命令与进程**：外部命令使用结构化参数并校验可执行文件和输入，不把不可信值拼入 shell；超时、退出码、标准输出和子进程清理有明确处理。
- **7.3 文件系统安全**：所有用户或来源派生路径限制在预期根内，考虑绝对路径、`..`、符号链接、大小写和覆盖；删除、替换和清理只作用于本次拥有的明确目标。
- **7.4 数据与秘密暴露**：日志、异常、Output、临时文件和测试产物不泄露凭据或超出声明范围的原始数据；对共享主机的文件权限假设明确。
- **7.5 资源与规模**：对输入规模、内存、磁盘、查询结果、递归、并发和外部等待有与用途相称的边界，不存在明显无界放大或宿主耗尽路径。
- **7.6 确定性与平台差异**：结果不依赖未排序遍历、当前目录、区域设置、默认编码、平台路径语义或未声明的全局状态；支持的平台差异在代码与测试中一致处理。
- **7.7 普通实现缺陷**：检查异常分支、错误条件、类型/Schema 错配、资源生命周期、重复执行、竞态和静默数据丢失；只有能给出具体触发与实际影响时才形成 finding。
