01开始之前

KAT 是一个可扩展的性能分析平台。你提供问题、数据位置和必要背景，Claude Code 通过 KAT 发现可用的分析方法、执行计算，再依据结果回答问题。

先认识四个常用概念
名称你需要知道什么
KAT Skills安装进 Claude Code 的四个任务入口，共用一套运行环境。
PACK一个团队维护的一组分析策略。可以由同事提供，也可以让 Claude Code 帮你开发。
WorkflowPACK 中回答某个具体问题的执行入口，声明所需输入。完成计算不等于结论已充分得到证据支持。
Session / RunSession 归集同一次分析；一次成功发布的 Workflow 执行形成一个 Run。继续查询时通常需要同时保存这两个 ID。

KAT 支持哪些数据和问题，取决于当前可用的 Workflow。发布包可能没有业务 PACK；安装成功也不表示已经具备启动耗时、CPU 或内存分析能力。先检查能力；没有匹配时，再决定获取或开发 PACK。

阅读与运行的前提不同。本页不需要网络。实际使用需要可正常工作的 Claude Code，以及选中 Workflow 要求的本地文件、工具或服务。数据必须位于 Claude Code 执行任务的主机可访问的位置。

02安装与首次启用

检查使用环境

先确保 Claude Code 已可正常使用。尚未安装时，参阅 Claude Code 官方安装说明（联网）。

KAT 运行平台当前要求
Linuxx86_64，glibc 2.28 或更高。可用 uname -m 和 getconf GNU_LIBC_VERSION 检查。
WindowsWindows 10/11 x86_64 客户端，仍为预发布候选；不等于已通过干净客户端正式支持验收。
其他环境macOS、ARM、musl Linux、Windows Server、Windows 7/8.1 不在当前 KAT 支持范围内。Claude Code 可运行，不代表 KAT 载荷可运行。

下载、校验并完整解压

  1. 从 KAT Releases（联网） 选择一个明确版本，下载同一 Release 的 kat-skill-版本号.tar.gz 和 kat-skill-版本号.tar.gz.sha256。rc 表示预发布候选。
  2. 核对压缩包的 SHA-256 与校验文件一致；不一致时重新获取对应版本，停止安装。
  3. 解压到一个空目录。解压结束后，应看到四个同级目录，手册位于其中的 kat/user-manual.html。
解压后的目录
解压目录/
├── kat/                 总入口、公共说明和运行环境
│   ├── SKILL.md
│   ├── user-manual.html  本手册
│   └── scripts/targets/  随包的 Linux 与 Windows 载荷
├── kat-analyze/         分析已有数据
├── kat-author/          创建和维护 PACK
└── kat-review/          复核已有分析

下列示例中的“版本号”替换为下载文件名中的实际版本。命令仅用于安装；日常操作使用后面的对话示例。

Linux · 在下载目录中校验和解压
version='版本号'
# 每一步成功后才执行下一步；使用一个尚不存在的目录。
sha256sum -c "kat-skill-${version}.tar.gz.sha256" &&
mkdir "kat-unpacked-${version}" &&
tar -xzf "kat-skill-${version}.tar.gz" -C "kat-unpacked-${version}"
Windows PowerShell · 在下载目录中校验和解压
$version = '版本号'
$archive = "kat-skill-$version.tar.gz"
$expected = ((Get-Content -LiteralPath "$archive.sha256" -Raw).Trim() -split '\s+')[0]
$actual = (Get-FileHash -LiteralPath $archive -Algorithm SHA256).Hash
if ($actual -ine $expected) { throw 'SHA-256 不一致，停止安装' }
New-Item -ItemType Directory -Path "kat-unpacked-$version" -ErrorAction Stop
tar -xzf $archive -C "kat-unpacked-$version"
if ($LASTEXITCODE -ne 0) { throw '解压未完成，不要使用这个目录' }

归档中的 Linux 载荷含符号链接。解压工具和环境必须支持保留链接及相应文件属性。若 Windows 报符号链接创建失败，应改用具备相应权限或能力的解压环境，再解压到新的空目录；不要忽略错误、只复制 SKILL.md 或混用另一版本的 Python。

让 Claude Code 找到四个 Skill

选择一个安装位置，将四个目录一起放进去并保持同级。推荐个人级安装，供本机不同项目使用。

范围四目录的共同父目录

个人级 · Windows%USERPROFILE%\.claude\skills\（文件资源管理器地址栏）；PowerShell 使用 $env:USERPROFILE。
项目级项目根目录/.claude/skills/；在该项目内使用 Claude Code。

Linux 可使用保留文件属性和链接的 cp -a 复制。Windows 可以在目标四目录均不存在时，把已校验的原压缩包再次用支持符号链接的解压工具解到 skills 目录。保留同一版本的全部内容。

重新打开该项目的 Claude Code 会话，输入下面的内容。只有能发现并调用相应 Skill，才算完成 Claude Code 侧的启用。安装位置规则可参阅 Claude Code 官方 Skills 说明（联网）。

03准备真实分析

从你实际遇到的问题出发，准备下面这些信息。示例中的 【方括号内容】 都要替换为真实信息；不知道的内容直接注明未知。

  • 输入：文件绝对路径或 Workflow 所需的来源位置、格式和采集工具。使用远程主机时，提供远程主机可见的路径。
  • 问题：发生了什么、预期是什么、你想比较或解释哪一段行为。
  • 范围：相关进程、线程、时间区间、设备与采集条件；有对照数据时说明对应关系。
  • 能力：若同事提供过 PACK，说明它的目录和用途。没有 PACK 时先发现当前可用能力。
在 Claude Code 中 · 先确认分析条件
/kat-analyze 我想分析一次应用冷启动耗时偏长的问题。
Trace： 【文件绝对路径】
采集工具和格式： 【实际工具、格式；未知项请写未知】
目标应用或进程： 【名称】
现象及关注区间： 【例如点击图标到首帧显示；给出你掌握的范围】
可用 PACK： 【PACK 目录；没有则说明没有】

请先确认已有 Workflow 能回答什么，以及还缺哪些输入。
没有匹配能力时说明缺口，先不要创建或修改 PACK。

冷启动只是表达问题的例子，不表示每套安装都包含冷启动 Workflow。若数据缺失、格式不适配或能力不存在，应先解决该项缺口。不要把“文件能打开”当作“能回答这个问题”。

路径不是文件上传指令。按你所在环境的要求准备可访问文件；连接凭据按来源工具的配置方式提供，不放进分析提示中的 Workflow 参数。参数可能进入操作日志。

04完成分析，读懂结果

输入和可用能力明确后，让 Claude 执行所选 Workflow。KAT 为新分析建立 Session，计算后保留成功 Run 的表格证据；Claude 据此组织结论。

在 Claude Code 中 · 开始分析
/kat-analyze 按刚才确认的 Workflow 和输入执行这次分析。
先直接回答我的问题，再给关键证据、结论适用范围和仍不确定的部分。
请保留本次 Session ID、相关 Run ID、PACK 和 Workflow 名称，方便继续追问。
如果现有证据不足以判断原因，请说明缺口，不要把推测写成已确认结论。

拿到报告后，检查四件事

  1. 有没有回答原问题：结论对应你提出的现象、对象和时间范围。
  2. 证据能不能定位：报告应说明使用了哪个 PACK/Workflow，并提供必要的 Session/Run、输出和查询证据。
  3. 事实和解释有没有分开：计数、耗时、排序是观察；“为什么发生”可能仍是推断。
  4. 限制是否明确：数据未覆盖、单位或时钟不明确、来源不完整时，应说明对结论的影响。

成功运行不是业务结论。Workflow 可能只组织其他 Workflow，不生成自己的输出表；有列但零行的表也可能是正常结果。这些情况都不能单独证明“没有问题”。

分析失败时，应得到停止阶段、具体原因和可用日志或报告位置。失败的顶层执行不会返回可用的本次 Run ID；预先创建的 Session 以及其中已成功发布的其他 Run 可能仍在，可以继续检查。

05追问、继续与独立复核

在同一次分析中追问

在 Claude Code 中 · 只查已有证据

暂时不要重新执行 Workflow；如果已有输出无法回答，请说明缺少什么。

查询已有输出和重新执行分析是两件事。需要新增计算时，明确要求在已有 Session 内继续；每次执行可能增加新的 Run。

换一个对话继续

保存原问题、报告、Session ID、相关 Run ID、PACK 位置及已验证的 KAT 版本。新对话仍须访问原 Data Home 和相关 PACK。只复制两个 ID 到另一台机器，不会带走原来的数据与环境。

原问题： 【问题】

Run ID： 【完整 ID；只知道 Session 时可省略】

只有 Session ID 时，可以查看其中的 Run；只有 Run ID 时，还需要所属 Session ID。KAT 不提供全局 Session 列表、隐式“上一次分析”或跨 Data Home 搜索。PACK 更新后取得的分析指南是当前版本，不是当时的历史快照。

请另一轮分析独立复核报告

在 Claude Code 中 · 按需复核
/kat-review 请复核【报告路径】。
原问题： 【问题】
Session ID / Run ID： 【对应 ID】
请逐条说明哪些结论有证据支持、哪些证据不足、哪些与证据矛盾或无法验证。

复核基于能取得的现存材料，不保证还原完整历史。新查询属于本次复核，不能证明原分析当时做过同样的查询。

06通过对话创建与维护 PACK

当已有能力无法回答问题，或你希望让同事复用一种分析方法时，使用 /kat-author。你负责说明目标、材料与验收口径，Claude 负责在指定目录实现和检查代码。

创建一个可工作的分析能力

在 Claude Code 中 · 创建 PACK
/kat-author 请在【PACK 集合目录的绝对路径】创建一个 PACK。
名称： trace-event-summary
标题： Trace 事件概览
维护方： 【真实团队或组织】
用途： 对我提供的真实文本 Ftrace 按事件类型计数，帮助检查采集内容。
输入： 【真实 Trace 的绝对路径、采集工具及已知时钟信息】
期望输出： 事件类型和计数，并解释数据范围和已知限制。
验收： 事件分类与总量能用独立检查核对；包含正常输入、空输入和不支持输入的处理测试。

请先检查可复用的数据能力，再创建骨架并实现 Workflow、分析说明和测试。
只修改新 PACK；完成后运行声明检查、测试和这份真实数据的分析，交付实际证据。

以上是开发需求示例，不是安装后必定存在的 PACK。目标目录与维护方不可虚构。实际参数、来源支持和边界由实现与验证确定；时钟信息未知时说明未知，不能凭空指定真实时钟。

你应能理解的 PACK 目录
trace-event-summary/
├── pack.toml       名称、标题、用途、维护方
├── README.md       使用、输入与交付说明
├── workflows/     回答分析问题的执行入口
├── datasources/   需要时添加的来源能力
├── helpers/       PACK 内部辅助代码
├── knowledge/     分析策略与来源说明
└── tests/         测试与受控样例

骨架目录生成且可被发现，只说明结构有效。必须继续实现真实能力、通过测试和运行验收，才能交付给使用者。无需给没有用途的目录添加占位实现。

修改已有 PACK

        ├── workflows/
        └── ...

先确认实际使用的 Data Home，不能把平台默认路径直接当作已选路径。开发目录和安装目录中的同名 PACK 若同时被发现，会发生冲突；保留一个要使用的发现位置，不依赖隐式覆盖顺序。Workflow 调用其他 PACK 时，相关 PACK 也必须在可发现范围内。

完成标准：接收环境能发现、测试并执行 PACK，且不再依赖发送方的目录。复制成功、测试通过与跨平台支持是不同的结论，只陈述实际验证过的范围。

09数据、依赖与版本维护

安装目录与 Data Home

四个 Skill 目录保存说明和运行环境。Data Home 保存分析 Session、用户安装的 PACK、日志与查询结果。更新 KAT 时，应保留 Data Home 和另行维护的 PACK 源码。

平台默认数据目录 / 固定配置文件
Linux$XDG_DATA_HOME/kat，未设置时为 $HOME/.local/share/kat；配置文件为该默认位置下的 config.json。
Windows%APPDATA%\KAT\data；配置文件为 %APPDATA%\KAT\data\config.json。

选择顺序是：非空 KAT_DATA_HOME 环境变量 → 配置中的非空 kat_data_home → 平台默认目录。配置文件始终在默认位置；即使环境变量优先，已存在的配置文件也必须可读且格式有效。

需要更换数据目录时

先由你创建一个可访问的绝对目录，再手工修改上述固定位置的配置文件，保留其他字段，仅增加或更新 kat_data_home。下面是 Windows 示例；实际路径要换成你的目录：

config.json 示例
{
  "kat_data_home": "D:/kat-data"
}

Linux 可使用形如 /home/你的用户名/kat-data 的绝对路径。KAT 不展开配置值中的 ~、$HOME 或 %USERPROFILE%。非空环境变量会优先；变更 Claude Code 的进程环境后需要重新打开相应会话。

完成手工调整后，告诉 Claude 再尝试操作，以实际结果验证。换目录不会迁移旧 Session；若要继续原分析，仍需使用其原 Data Home。路径或配置无效时 KAT 会失败，不会自动换用另一个目录。

管理额外的 Python 依赖

当前版本提供使用内置 Python 的 pip 管理第三方库的方式。分析或只读检查遇到缺库时先报告缺项；你明确要求安装后才执行。已授权的 PACK 创作可以补装任务所需依赖。

在 Claude Code 中 · 明确安装并验证依赖
/kat 请在当前这套 KAT 的内置 Python 中安装【包名与需要的版本】。
确认实际安装版本、依赖冲突和隔离导入是否正常，再验证【受影响的 PACK 目录】。
请说明安装结果和仍未通过的检查。

同一套部署中的 Runtime 和全部 PACK 共享此环境。不要将库装到系统 Python 后就认为 KAT 可以使用，也不要通过复制另一套环境的文件补齐。安装成功不等于 PACK 验收通过；原生库可能另需系统依赖。更多命令见随包的Python 依赖说明。

升级 KAT 或更新 PACK

  1. 记录当前版本、额外安装的库、PACK 位置及需要保留的分析信息。停止使用这套部署的任务。
  2. 下载并校验新版本，将其解压到新的空目录，核对四个 Skill 与载荷完整。
  3. 把旧的四个 Skill 目录移到 skills 目录之外留作回退，再把新版本四目录成套放入原位置。不要合并新旧文件；其他 Skill 和 Data Home 保持不动。
  4. 按交付说明重新安装所需额外 Python 库，重新打开 Claude Code，完成自检、PACK 测试和一次实际分析。

新版本带来一套干净 Python 环境，不自动保留后来加装的库。KAT 预发布阶段不承诺公共接口和数据布局跨版本兼容；升级前阅读对应 Release 说明。保留旧文件不等于旧版本能读取新版本产生的状态。

单独更新 PACK 时，停止相关任务，核对同事提供的版本要求，整体替换选定的 PACK 目录并重新验收。不同目录内的同名 PACK 没有自动优先级。

删除不再需要的分析

删除以整个 Session 为单位。先保存需要的报告和证据，再明确指定要删除的 Session。此操作永久删除其中的 Runs、输出和共享物化；不提供单个 Run 删除、自动清理或恢复功能。有活动操作时删除会失败，应在操作结束后处理。

在 Claude Code 中 · 明确删除范围
/kat 请删除 Session【完整 Session ID】。
我已保存需要的报告，明确要永久删除这个 Session 的全部 Run、输出和共享物化。
不要处理其他 Session。

Session 外的操作日志和查询结果文件不会随之删除。需要进一步清理时，应根据明确的文件位置另行管理，不凭猜测删除整个 Data Home。

10常见问题

遇到的情况先检查什么下一步
找不到 /kat是否位于个人或当前项目的 .claude/skills/kat/SKILL.md，有无多套一层目录。成套检查四目录，重新打开该项目会话；提供安装路径和 Claude Code 的实际提示。
缺少载荷或 Python是否完整解压同一版本，解压时有无符号链接或权限错误。校验原包，解到新的空目录。不要用系统 Python、Cargo 输出或另一个版本拼装。
平台不支持KAT 执行所在主机的 OS、架构和 libc，不只是终端所在的桌面。使用当前支持的环境，或等待对应平台支持；不要把拒绝当作分析失败结果。
没有 PACK / 没有匹配 Workflow是否提供实际 PACK 根目录，当前能力是否真的覆盖问题。获取适配 PACK，或明确发起 /kat-author 开发请求。
PACK 重名Data Home、随包目录和显式目录是否同时发现同名 PACK。选定一个发现位置，排除重复；不能靠路径顺序覆盖。
缺少依赖 / 外部解析器PACK 的交付说明、内置环境实际库版本、工具路径及配置。按明确缺项补齐，并重新检查、测试和执行。不要把依赖安装成功当作分析完成。
Data Home 无效固定配置文件语法、环境变量、所选路径是否绝对且可访问。根据诊断手工修正后重试；不要自动改用另一目录造成分析分散。
已有 Run 无法继续Session/Run 是否成对、Data Home 是否相同、当前 PACK 和文件是否仍可用。提供原报告和已知 ID；资料缺失时标明限制，不猜 ID 或重建历史。
没有结果表 / 结果为空Workflow 的用途、实际输出和需要查看的子 Run。依据实际证据解释；不能直接得出“没有问题”。
测试或运行失败具体阶段、错误摘要、KAT 返回的日志或测试报告位置。用 /kat-author 明确请求诊断或修复，并限定修改范围。

向维护者求助时，提供 KAT 版本、主机平台、Claude Code 版本、PACK 来源及已验证版本、最短复现步骤、错误摘要和明确相关的日志位置。分享材料前去掉凭据与无关业务内容；没有取得的信息直接说明缺失。
