# 分析结果契约

每次分析只以以下三种状态之一交付。先陈述状态，再给足以复核的最少事实；不输出完整 KAT Response、完整表、原始 Guide 或原始日志。公共失败与补问规则见[命令合同](../../kat/references/command-reference.md)。

## 已完成

按以下顺序交付：

1. 一份直接回答用户问题的综合结论，复用仍适用的已保存正文，不逐节点交付独立报告或直接拼接 Guide。
2. 少量可追溯依据：Session ID 与实际事实出处；采用过知识时提供对应材料 ID，执行过 Workflow 时提供真实 PACK/Workflow 与 Run ID，只列实际存在且采用的 Output 和查询材料。不要求同时存在两类依据，不补造执行或查询证据。处理不同范围、矛盾或重叠的证据，不重复计数。
3. 适用范围、假设与不确定性；区分恢复的原解释与新增证据形成的后续判断。Run 的 Guide 是执行时快照，当前 PACK 的文件不能冒充历史依据。
4. 报告保存状态及可继续分析的 Session ID。新报告保存成功后才承诺该正文可跨任务恢复，交付结论应与保存内容一致。成功 Response 已完成确认，不再为交付重读记录；已有适用报告不必重复保存。
5. 基于实际采用的方法和现存证据形成的可选下一步；证据足够即停止。

独立知识与 Workflow Guide 指导方法，不是数据证据。不要把 Provider Guide、Provider 实现或未执行 SQL 当作事实依据。恢复的方法与新增事实分别说明；换方法后核对受影响结论。未采纳的引用、外部资源及全部输入不保证可恢复，缺失时如实说明。

任务是否完成由目标与必要事实决定，不由是否有 Run 或报告树节点决定。实际执行过 Workflow 时，Run 发布、必要节点解释保存与总报告保存是不同完成点；纯知识任务直接保存总报告。部分进展不能冒充完整结论。

## 需要补充信息

先按[共同流程](analysis-flow.md)恢复已有信息，仍缺目标、材料或所选能力的必需输入时，只请求最小必要信息，说明其用途。不要求用户选择知识还是 Workflow，不要求用户提供可由公开 inspection 获取的表结构。

## 执行失败或受阻

没有匹配 PACK 或两类能力均不匹配、所需能力 inspection 失败、必需引用缺失、来源准入或解码失败、失败 Run、失败 Query，以及无法继续的记录损坏或保存失败都属于这一状态。发现受限不是能力不存在；不影响所选方法完成任务的限制也须说明，不将所有发现失败一律当作全任务失败。说明已确认事实、最后成功保存的进展与最小下一步，不能把部分输出或未保存报告描述为完整且可恢复。

恢复与保存失败按共同流程处理。区分“分析判断已经形成”和“本次保存尚未确认”；已确认缺口或部分判断能够保存时及时保存，不自动转为 PACK 创作或独立复核。
