# 分析记录支持只凭 Session ID 跨任务恢复

[Issue #298](https://github.com/maokelong/kat-cli/issues/298) 要求用户离开原 AI 任务后，仅提供 Session ID 就能找回原问题、报告组织、AI 串联依据、已形成解释及原 Guide 和关键证据。现有 Run Manifest 只能证明成功执行及直接 `child_runs`；模型上下文和 Session 外的查询文件不足以满足恢复要求，因此新增 Analysis Record 作为正式持久状态，不能把它当作可重建缓存。

一个 Session 对应一个分析目标和一份当前记录，独立新目标创建新 Session。记录与 Run Manifest 分离，后续解释不改写已发布执行事实。报告只有一个代表用户问题的隐含根；只持久保存一份有序 Run 节点，每个节点持有报告父引用、已知 AI 选择依据和当前解释。同父节点的相对数组顺序是报告顺序，树由节点派生，不另存 `tree` 或 `choices`。非根父引用由真实 `child_runs` 核实；一个 Run 只占一个节点，共享证据使用引用。

AI 顶层调用的多个 Run 可以成为报告根下的兄弟分支，选择依据保存在目标节点，但不冒充程序父子边。组合 Workflow 仍用确定性 Python 和 `ctx.run()` 执行，完成后由分析 Skill 按需使用父子各自的 Guide 与证据，形成轻量解释并汇总一份最终报告；执行期间不调用模型，也不强制解释所有叶子。

Guide inspection 与 Output Query 通过显式归档参数直接保存本次实际 Guide 字符串或 `null`、SQL、来源、列及少量原始 NDJSON。材料不可由 AI 抄写后充当原始事实；完整表仍引用 Run Output。执行前 Guide 可先属于 Session 与 Workflow，执行后核对节点身份。恢复直接读取记录与原材料，不要求当前 PACK 或普通查询文件仍存在；采用新 Guide 或补充证据属于后续更新。

首版用一个 JSON 保存当前记录与归档原文，复用标准序列化、文件锁和同目录完整替换，不引入数据库、通用图执行器或多文件材料提交框架。记录读写先取得 Session 使用租约，再使用独立稳定分析锁：完整读取期间持共享锁，写入与原子替换期间持独占锁，避免 Windows 打开的读取句柄妨碍替换。所有领域更新比较预期修订号；材料追加返回追加前后修订号，Skill 不得用追加后的数字跳过未读取的并发修改。失败保留先前完整状态，损坏明确诊断；提交后响应失败由重新读取确认，不回滚记录或重跑 Workflow。

材料身份、节点解释版本和记录修订号各司其职。解释引用实际采用的材料及其他节点的解释版本；改变解释时沿真实依赖使旧消费者和总报告失效，跨分支同样适用。归档尚未采用的新材料不使全部结论失效，报告重排只使旧总报告失效。有效状态只证明登记依赖未过期，不证明文字结论正确或证据充分。

本决定局部替代 [ADR-0078](0078-workflows-compose-through-context-run.md) 中中间解释只存在于模型上下文、不成为持久对象的限制，以及 [ADR-0082](0082-kat-review-rechecks-existing-evidence.md) 首版不提供分析记录与 Guide 快照的范围约束。ADR-0082 的成套 Skills、独立事后复核和不自动触发第二轮 AI 保持不变；`kat-review` 可以只读已存报告与依据，不更新原记录。

恢复保证以最近成功保存的当前状态为界，不包含完整调用历史、全部失败尝试、所有旧解释版本、运行中 Python 续跑或跨机器复制。验收同时覆盖 CLI 集成行为与全新 AI 任务实际按 Session ID 恢复；仅验证 JSON 读写或在原对话重复展示不能替代这两个边界。
