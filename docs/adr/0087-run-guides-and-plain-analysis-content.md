# Run 固化 Guide，分析记录只保存正文并按需恢复

[Issue #298](https://github.com/maokelong/kat-cli/issues/298) 的跨任务恢复目标保留，但由 AI 手动归档 Guide、维护报告父引用、拆分解释字段和登记版本依赖增加了不必要的操作。用户确认将程序职责收敛为保存执行事实与分析正文，解释是否可复用以及是否重新汇总由 AI 判断。详细生命周期及验收见[设计规格](../specs/analysis-lifecycle.md)，程序与产品 Skill 按同一合同交付。

每次 Workflow 在业务执行前由程序捕获自身 Guide 正文或未声明事实，随成功 Run 一起发布；顶层和 `ctx.run()` 使用同一规则，不依赖 Analysis Record。父失败不能撤销已经发布的子 Run 和 Guide。顶层成功结果提供自身 Guide、Output 元数据与直接子 Run ID，不递归加载文档；`inspect run` 无需当前 PACK 即可重读同一核心内容。`inspect workflow` 只承担当前可调用能力的用途与参数准备，不再返回分析 Guide。Run 的 Guide 不属于 AI 分析状态，也不会随解释更新而改变；普通恢复不能以当前 PACK 内容补造历史。明确使用新版 Guide 重析旧 Run 的路径仍待单独确定。

一个 Session 保留一个目标和一份当前 Analysis Record。节点只有 Run 归属与 `content` 正文，总报告同样保存一个 Markdown 正文字段；必要的事实、证据出处、取证原因和限制自然写入正文，不拆分 `selection`、`uses` 或解释字段，也不分配供节点相互引用的解释版本。程序不解析正文建立依赖图，不管理有效/失效/待汇总状态；修改目标或节点后，其他正文和旧总报告原样保留，AI 自行核对并按需更新。

首次保存某个 Run 正文即将它选入报告。报告树由已保存节点和真实直接 Run 父子关系派生，直接父尚未选入时挂隐含的问题根，父后来选入后自动归位；不持久保存另一份父引用，不跨越未选中的中间父节点。AI 临时串联的独立 Run 为根下兄弟，其必要原因留在正文中，不伪造程序调用边。`ctx.run()` 的执行与 Catalog 返回合同保持不变，AI 在执行后按需解释必要节点，不强制遍历全部叶子。

分析 CLI 只保留 `show/save`。首次 save 创建目标，后续按 Run 或总报告增量保存，省略内容保持原样。查询程序继续保存实际 SQL、来源、列和关键 NDJSON 原文；正文可以指出材料身份，但程序不维护正文到材料的解释依赖。保存继续使用 Session 租约、稳定分析锁、记录级并发比较和完整替换提交，避免旧写覆盖与半次更新；归档返回追加前后修订号，不能用新数字跳过未读并发修改。不存在、损坏与未知格式分别处理，失败不覆盖先前完整记录，Session 删除统一管理记录和材料生命周期。

解释形成后及时保存，再用于后续分析；保存与读取相互独立。当前上下文已保留必要解释和成功保存结果时直接汇总，不要求重读记录。新任务、上下文缺失、并发冲突或保存响应不确定时，才通过 `analysis show` 恢复或确认；程序不检测上下文压缩，也不增加压缩状态。交付总报告前保存正文，成功响应即可确认，不额外安排一次回读。记录保证最近成功保存内容可恢复，不保证文字结论正确，不保存模型内部推理过程或执行栈。

本决定替代 [ADR-0086](0086-analysis-records-enable-cross-task-resumption.md)，保留其 Session 所有权、真实查询材料、可靠提交与恢复目标，取消手动 Guide 材料登记、手工挂树、结构化选择、解释依赖版本和自动失效。局部替代 [ADR-0078](0078-workflows-compose-through-context-run.md) 中“中间解释仅在上下文”“按 Run 读取当前 PACK Guide”“不新增 inspect run”和顶层结果不含 Guide/直接子 ID 的条款；其确定性执行、独立子 Run、Catalog、发布与失败边界继续有效。
