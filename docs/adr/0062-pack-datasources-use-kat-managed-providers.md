# PACK Datasource 使用 KAT 管理的 Provider

PACK Datasource 是所选 PACK 中由 Workflow 直接 import 的普通 Python module 或 factory。它拥有来源配置解释、定位与解析、来源内 SQL 和参数、私有 catalog、类型转换、语义透明缓存以及来源特定长期物化策略；它没有独立的平台身份，不注册、不扫描、不进入 `pack.toml`，也不增加 `kat import` variant。需要查询能力时，Datasource 创建按公开结构协议实现的 Source executor，并显式使用当前 Workflow Context 的 `ctx.provider(executor)` 取得 operation-bound Provider facade。该 facade 由 KAT 固定实现；PACK 不能直接构造、继承或替换它，也不能通过 Workflow input 注入任意 Provider 实现。

Pack Authoring API 公开 `SourceExecutor`、`ParquetSource`、`Provider` 与 `Table`。Source executor 的一次 `execute()` 只在 context manager 内交付一个具有明确 Arrow Schema 的 `pyarrow.RecordBatchReader`，或一个消费期间保持稳定的单表 `ParquetSource`；它不接收 Query result name、Runtime landing path、Run Output 发布能力或 KAT 融合 Session。来源方言、连接、解析、私有 catalog 和来源资源关闭实现属于 executor；结果命名、query scratch、通用 Parquet sink、本地自动注册、Table 构造、Context 状态与 operation 结束时的 executor 关闭编排属于 KAT Provider facade。

`Provider.query(sql, params=None, name=None) -> Table` 是同步、eager 的单来源查询边界。facade 在任何来源 I/O 前校验并保留 operation-local 名称，分配私有 scratch，进入 executor context，完整消费单表结果，关闭 sink，正常退出 executor context，把私有 partial 形成 `outputs/<name>.parquet` backing，再自动注册同名本地关系并返回 `Table`。显式名称复用 KAT 可移植 Output name 规则；缺省名称是只基于原始 SQL UTF-8 字节的 `q_<sha256>`。来源执行、stream、sink、context 退出、finalize 或注册在 `Table` 返回前任一步失败，都不产生 `Table`，并使当前 Context 不可发布；PACK 即使捕获异常，也不能继续 Provider query、`ctx.sql()` 或成功 Output 发布。query-level context 正常退出属于查询成功条件；Workflow 结束后，Runtime 对每个已登记 executor 恰好调用一次 `close()`，并在某个调用失败后继续关闭其余 executor。operation-level `close()` 和不可见中间文件删除是尽力清理，失败只追加 warning，不覆盖已有业务错误，也不改变已经正确形成的 Output。

KAT 同一次 Workflow 执行中存在两个隔离的 DataFusion 执行面。Workflow Runtime 继续独占 KAT fusion Session、Table Grant、UDF registry、operation-local catalog 和跨来源组合；PACK 不能取得或任意修改该 Session。Source executor 可以为本地 Parquet 等来源创建自己的私有 DataFusion Session，但该 Session 只能解释 executor 的来源内 catalog，不能获得 KAT Dataset、Execution Lease、Provider Table 或融合 registry。两个执行面只通过 executor 交付的 Arrow stream 或单表 Parquet 相连。`ctx.sql()` 只查询已经注册到当前 operation 的本地关系，不发现 Provider、不访问远端 catalog，也不触发来源执行；现有 `ctx.from_arrow(pyarrow.Table)`、DataFrame、Expr 与官方 functions 合同保持不变。

Workflow Context 新增受 Execution Lease 约束的 `ctx.provider(executor)` 和只读 `ctx.datasource_root`。生产 `ctx.datasource_root` 只暴露当前 PACK 在所选 KAT Data Home 中的 `KAT_DATA_HOME/datasources/<pack-name>/`，不暴露整个 Data Home、Run workspace 或其他 PACK 的目录；Datasource 自己定义其下的 artifact key、布局、格式、完整性、重用和清理。Provider query 可以维护不改变查询语义的私有缓存，但用户命名、跨 Workflow 复用的长期物化必须由 Datasource 显式函数或专用 Workflow 发起，不进入统一 Provider contract。Context 与 Provider 都不能跨 operation 复用，失效 Lease 必须在任何来源 I/O 或路径访问前拒绝调用。

`Table` 是已经完整本地化的不可变单表句柄，只公开只读 `name` 与 Arrow `schema`，不公开 backing path、来源连接或延迟查询计划。`Table.name` 同时是 operation-local relation name、候选 backing name，并在该 Table 被直接返回时成为 Run Output name；Mapping 中的 key 必须与 `Table.name` 完全一致。Workflow 可以返回单个 `Table`、Table Mapping、现有 DataFrame，或由两者组成的 Mapping；DataFrame 继续使用单值 `main` 或 Mapping key 的既有命名和惰性物化规则，但其 Output name 不得与当前 operation 中任何 Provider Table 重名。Runtime 在所有惰性 DataFrame Output 完成前保留融合输入；直接发布 Table 时复用已经形成的 backing，不重新执行来源 SQL 或重新物化同一结果。

`ParquetSource` 只能表示一个普通 Parquet 文件或一个逻辑单表的 Parquet dataset 目录，不能表示多表根目录。Runtime 把 scratch 内来源 move/rename 为独占 backing；scratch 外来源必须通过具有写时分离语义的 clone 或字节复制形成独立 backing，不使用 hard link 或 symbolic link。`outputs/<name>.parquet` 因而可以是普通文件，也可以是至少含一个可读 part、具有一致 Schema 的单表目录；零行目录仍必须包含一个携带 Schema 的零行 part。现有 DataFrame Output 继续物化为单个 Parquet 文件，只有 `ParquetSource` 可以保留单表分片目录形态。Table、Run Manifest、Runtime Response、Output Query 与 PACK 都不观察或记录这一 physical kind；Runtime 仍负责完整 Schema、总 `row_count`、可读性和发布证明。

旧 Data Import Datasource type、Dataset、`required_tables`、Test Dataset 与 `kat import` 在迁移期继续存在。旧类型仍是 CLI/Rust 内的封闭集合；新 PACK Datasource 不是其插件机制或新增 variant。Runtime 先按既有 Table Grant 注册旧 Dataset relations，随后由成功的 Provider query 把 Table 注册到同一个 operation-local catalog；`required_tables` 只声明和约束旧 Dataset relations，不声明 Provider、来源 SQL 或 Query result name。Provider 名称与旧 Dataset relation、既有 Provider Table 或其他已注册 relation 冲突时，必须在来源 I/O 前失败并 poison Context，不覆盖、不 shadow，也不增加 Dataset-to-Provider adapter、Binding 或第二套融合 API。旧模型的最终删除与真实 PACK 迁移属于后续独立决定，不在本切片中发生。

`kat test` 的每次 `kat_run` 仍创建独立的 execution plane、Table Grant、Execution Lease、Workflow Context、临时执行目录和 Outputs；同一 pytest test 内的 `ctx.datasource_root` 则映射到该测试 `tmp_path/datasources/<pack-name>/`，使多次 `kat_run` 能验证显式物化后的复用。不同测试的根彼此隔离，测试结束后不写入生产 KAT Data Home。Provider fixture 只提供受控的来源输入和非敏感配置，不成为 Test Dataset、平台注册项或另一套 Provider 构造入口。

本决定部分取代 ADR-0001、ADR-0005 与 ADR-0026 中“DataFusion 只属于 Runtime、PACK 自建 SessionContext 一律不受支持”的绝对表述；KAT fusion Session 的 Runtime 所有权和 `ctx.from_arrow()` 合同继续有效。本决定部分取代 ADR-0012 与 ADR-0022 中由 `kat-datasource`/CLI 统一拥有全部 Datasource type、External PACK 不能扩展 Datasource 的表述；旧 Data Import Datasource type 在迁移期仍保持封闭。本决定部分取代 ADR-0015 中 Workflow execution plane 只能注册 Table Grant relations 的表述，但不改变旧 Dataset relation 的 `required_tables` 强制。本决定补充 ADR-0016 的测试生命周期。本决定部分取代 ADR-0032 中 Context 恰好只有三个方法以及 Workflow Output 只接受 DataFrame 的决定；既有方法、DataFrame Output、Execution Lease、显式 Context 和不暴露 Dataset 路径的原则继续有效。本决定部分取代 ADR-0055 中把候选 Output 描述为文件并以 file stem 表达物理形态的表述；可移植 Output name、Runtime 数据面所有权和 Manifest/Response 合同继续有效。ADR-0043 的薄 Query Engine 原则继续有效：PACK 不能取得或修改 KAT fusion Session，来源内私有 Session 不属于该执行面。
