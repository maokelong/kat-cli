# 用户授权后 Skill 可代表用户编辑 Data Home 配置

## 决策

平台默认 KAT 数据目录中的 `config.json` 仍是用户维护的 KAT 私有应用配置，其位置、字段和加载语义不由 Skill 定义。用户仍是配置选择和持久修改的决定者；KAT Skill 只有在用户明确授权后代表用户编辑，并且授权前还必须由用户明确要求更换 Data Home、提供目标路径，并确认修改已展示的配置文件。

Skill 写入前必须展示当前平台的默认 Data Home 与固定 `config.json` 路径，并且只接受已存在、可访问的绝对目标目录；不展开 `~`、`%USERPROFILE%`、`$HOME` 等缩写。一般的分析请求、用户接受默认位置或仅设置进程环境变量，都不构成配置写入授权。

文件不存在时，Skill 可以创建父目录和新的 JSON object。文件已存在时，Skill 必须先严格读取并确认它是有效 UTF-8、合法 JSON object，且已有 `kat_data_home` 缺失、为空或为字符串；随后只更新 `kat_data_home`，保留未知字段及其值。JSON 字段顺序和缩进不是契约。

Skill 不直接编辑、截断或覆盖最终 `config.json`。它必须先读取原始字节，记录“文件缺席”或已存在文件的 SHA-256，再在最终文件的同一目录以不可预测且不覆盖已有条目的名称创建临时文件。更新后的完整 JSON 只写入该临时文件；关闭后重新读取，确认它仍是合法 object、`kat_data_home` 等于规范化目标，且所有未知字段的值保持不变。初始 SHA-256 只用于证明提交前失败没有改变原文件，不作为并发控制机制。

只有当前环境提供并明确保证同目录原子发布语义时才可继续：原文件缺席时使用禁止覆盖的原子创建，原文件存在时使用原子替换。不得先删除最终文件、以复制代替原子发布，或在工具无法说明该语义时猜测。缺少该能力时按受阻交付，不修改配置。多个写入者同时修改配置不在本决策范围内；已存在配置出现多个已授权原子发布时，最终内容由最后完成的发布决定。

原子创建或替换成功是配置写入的提交点。提交点之前的任何失败都必须清理未发布临时文件，并保持最终文件的缺席状态或原始字节不变。提交成功后的 KAT 运行失败不回滚用户已授权的配置修改。本决策不承诺操作系统崩溃、断电或底层文件系统损坏时的额外持久化语义。

成功写入后，Skill 只为用户当前请求的 KAT 进程设置同一路径的 `KAT_DATA_HOME`，使本次操作立即使用新目录；它不修改用户的全局环境。KAT CLI 与发行制品仍不创建或写入 `config.json`，CLI 继续拥有 Data Home 选择和运行时失败语义。

## 理由与取舍

用户通过自然语言请求更换 Data Home 时，如果只能得到手工编辑说明，仍需理解平台配置位置、JSON 合并和当前进程环境。显式授权后的代理编辑让 Skill 完成用户已经决定的机械步骤，同时把配置所有权、目标目录选择和持久写入权限留给用户。

代价是 Skill 必须承担保留未知字段、拒绝覆盖损坏配置、使用当前环境可说明的原子文件操作，以及准确报告失败阶段的责任。本决策不增加通用配置编辑能力，也不授权 Skill 修改其他字段、其他应用配置或用户全局环境；并发写入协调仍由调用环境负责。

## 与既有决策的关系

本决策只取代 ADR-0060 的配置写入责任：`config.json` 不再要求用户必须亲手编辑，Skill 可以在上述明确授权边界内代表用户编辑。ADR-0060 规定的固定配置位置、配置结构、来源优先级，以及所有来源的配置加载、合并、校验和选择语义继续有效；该文件仍不是 `SKILL.md` 定义的配置格式或随 Skill 发布的载荷。
