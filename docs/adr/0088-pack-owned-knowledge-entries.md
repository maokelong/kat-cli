# PACK 提供不依附 Python 的知识入口

实施跟踪：[Issue #312](https://github.com/maokelong/kat-cli/issues/312)，实现与验收状态见设计规格。

报告模板、排查方法、判断准则等经验知识不一定具有有意义的 Python 程序入口。KAT 允许 PACK 提供可独立发现和选用的知识入口，由 AI 应用知识完成任务；PACK 可以只有知识入口，也可以同时包含知识入口和 Workflow，所有权与发布责任继续遵循 ADR-0028。

PACK 可承载性能分析之外的经验知识，例如通用代码评审或团队交付规范；知识领域与用途由 PACK 声明，平台不把性能分析设为知识入口准入条件。KAT 默认提供的能力仍以性能分析为主，通用知识机制不承诺平台已经具备任意领域的实际能力。

知识入口不要求先执行 Workflow，也可以指导 AI 按需选择和调用已有 Workflow，再根据结果继续判断。应用知识本身不构成 Run；实际 Workflow 执行继续遵循既有确定性执行和 Run 发布合同。无需用空 Python 入口或占位 Run 承载纯知识任务。

找不到匹配的知识入口或 Workflow 时，明确报告能力缺口，不自动转入无入口的任务执行。只有用户授权后，才进入经验整理与 PACK 创作流程；临时整理的经验不自动成为已发布能力。

知识入口指导 AI 完成任务，可以涉及判断、追问和多次取证；Workflow Guide 解释所属 Workflow 的结果及其适用边界。两者保留不同职责，但可以引用同一份经验文档，避免重复维护；共享文档不改变 Workflow Guide 的解释作用域，也不建立新的程序调用关系。

每个知识入口采用 Skill 风格的 Markdown 声明：头部提供 `name` 和 `description`，正文描述方法、适用边界和交付要求，并可按需引用模板、案例或共享知识。入口位于 `PACK/skills/<入口名>/SKILL.md`，专用材料可放相邻 `references/`，与 Workflow Guide 共享的知识由 PACK 的 `knowledge/` 维护。发现阶段先提供名称和描述，选中后再加载正文与任务需要的引用材料；入口仍随所属 PACK 维护和发布，字段校验与选择器由设计规格细化。

首版可由 KAT 读取并保存快照的知识引用限定为所属 PACK 内的 UTF-8 文本文件，包括 Markdown、文本模板和代码示例；以 Markdown 相对链接表达，按包含链接的文件定位目标。相邻材料与共享知识均可引用，最终解析的目标必须位于同一 PACK。图片与 PDF 不进入首版知识读取和快照合同；用户文档、网页及这些媒体可通过已授权工具作为任务材料读取。跨 PACK Workflow 继续按公开名称调用，任务材料不因此成为本入口的 PACK 知识引用。

纯知识任务同样支持跨任务恢复，沿用 Analysis Session 与 Analysis Record 保存目标和已形成的结果正文，用户可凭 Session ID 找回并继续。没有执行 Workflow 的任务不要求存在 Run 或报告树节点；后续实际执行 Workflow 时，仍在同一目标所属 Session 中保存真实 Run 与必要解释。不另建知识任务身份或记录体系。

任务保存实际采用的知识入口正文与已读取并采用的引用材料，形成所属 Session 的知识快照；不要求预先归档全部 PACK 或尚未采用的引用。AI 面向 Session 选用入口或引用时，由 KAT 程序读取原文、保存快照，再将同一份内容交给 AI；仅浏览能力不创建任务快照。恢复任务默认沿用该快照，不随 PACK 升级自动替换方法依据；明确要求更新方法时才采用新版，并保存新采用的知识及对既有结果的影响说明。原知识缺失时说明恢复限制，不以当前文件冒充旧依据。

公开操作区分只读的 `kat inspect knowledge` 与指定 Session 的 `kat knowledge read --session S`。前者用于发现和浏览当前 PACK 知识，不创建任务记录；后者用于任务选用并按需保存快照，成功后返回保存的原文。遵循已确定的原知识恢复规则，同一 Session 再次读取已保存知识默认返回快照，不因当前 PACK 变化重新采用新版。

明确采用新版知识时保留旧快照，新增具有独立材料 ID 的不可变知识快照；结果正文按需注明实际采用的材料 ID。同一入口只有一份已存快照时可按名称读取；存在多份时须明确材料 ID，否则报告歧义，不按时间猜测。复用 Session 的材料保存与读取机制，不建立额外版本依赖图，也不因更新方法而覆盖旧结论原有的方法材料。

知识入口允许 AI 使用当前任务已授权的通用工具读取文档、搜索资料、检查源码等，以应用经验知识；材料不必先转换成 Run Output。已有 Workflow 提供的程序能力优先复用，实际调用继续遵循对应输入、执行与结果合同。知识入口本身不增加来源访问、外部操作或消息发送授权。

首版交付知识入口的发现和选择、正文及引用的按需读取、知识快照、结果保存与恢复，验收同时覆盖纯知识任务和知识驱动 Workflow 取证。纯知识路径必须全程没有 Run；混合路径保留真实执行与解释；两条路径都验证 PACK 更新或移除后原方法依据仍可恢复。具体范围与验收见 [设计规格](../specs/pack-knowledge-entries.md)。

本决定扩展 ADR-0078 中知识只能依附 Workflow Guide 的能力入口边界，并在 ADR-0017 的固定 PACK 布局中增加 `skills/` 知识入口树；Workflow 仍是具有 Python 入口的确定性程序，AI 决策发生在各次程序执行之外。知识入口任务需要调整当前 `kat-analyze` 必须先选定并执行 Workflow、通用工具只用于准备 Workflow 输入的约束，匹配知识入口后可按其方法直接处理任务材料。具体选择器、声明校验、更新方法与任务记录接口见设计规格，本决定不声明这些能力已经交付。
