kat-rs Analysis Runtime Logical Architecture

Target logical view: kat-rs-skill selects or authors a pack, submits a run request through REST/OpenAPI, and writes the final report from daemon-produced evidence.

View Scope

  • This is a target logical view, not a process, port, container, or deployment topology.
  • It shows how skill selects or authors a pack resource and calls the daemon API with pack reference plus inputs.
  • Main path: question -> pack selection -> REST/OpenAPI run -> daemon pack expansion -> operator execution -> evidence-backed report.

Pack Boundary

  • Manifest indexes pack catalog, table/resource list, and atomic operators for selection and discovery.
  • Business Pack carries pack.yaml, flow.yaml, brief/examples, and pack-local private resources.
  • Resource Library contains shared flows, query/grep/summaries, and schemas reused across packs.

Execution Rules

  • kat-rs-skill calls the REST/OpenAPI surface to submit runs, inspect run state/diagnostics, and read evidence.
  • kat-rs-daemon loads the selected pack resource, expands it inside the orchestrator, schedules operators, and commits run facts/evidence internally.
  • The binding mechanism is the daemon-owned context topic store, not a new capability class.
  • Subscribe and publish are data movements between operators and the binding store, so they appear on the arrows.
  • Pub/sub does not schedule execution; DAG, branch, and loop semantics stay in the orchestrator.
  • Atomic operators are split into logic operators and data lookup; composition is explicit in workflow.

Organized as one target logical view with stable color semantics, labeled connections, explicit boundaries, and key design tradeoffs.
