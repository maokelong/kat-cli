# 角色检视

对同一份完整交付进行三次独立检视，分别回答：

- 业务主管：这笔工程投入是否值得；
- 架构师：这份交付能否由后续成员低成本接手和演进；
- Infra 专家：通用基础设施是否优先复用了成熟生态。

这是只读 review。可以读取仓库、PR、关联 issue/SDD/ADR、依赖清单、已有验收证据和必要的官方技术资料；不运行测试，不修改代码，不执行外部写入。证据不足时报告证据缺口，不替作者补充主张。

## 执行

1. 确定检视对象。优先使用用户指定的 PR、commit 或 diff 范围；未指定时，检视当前分支相对其 merge base 的完整交付，并在结果中说明这一假设。
2. 建立共享检视材料：交付目标、关联 issue/SDD、PR 描述、完整 diff、所有变更文件的完整内容、相关 ADR、依赖清单和已有验收证据。diff 用于识别改动及寻找评论挂点，完整文件用于理解实际流程。
3. 并行启动三个 subagent。每个 subagent 获得相同的检视材料、一个角色定义和统一输出格式；不得读取其他角色的过程或结论。
4. 收齐三个结果后，主 Agent 检查角色边界，合并结论与证据均相同的问题，保留不同角色对同一事实的不同判断，并按角色汇总。

完成条件：三个角色都覆盖了本角色的全部判断项，并分别给出评分以及问题列表或明确的无实质问题结论。

## 报告标准

检视范围是本次交付新增、修改或形成承诺的代码、配置、文档、ADR 和验收证据。历史问题仅在本次交付引入、扩大或依赖它时报告。

报告所有会实质影响本角色目标的问题，不凑数。每个结论必须由检视材料或可核验的官方技术资料支持；无法核验的猜测不构成问题。

严重级别：

- `P0`：结论足以说明当前交付不应合并；
- `P1`：合并前应处理的实质问题；
- `P2`：不一定阻断合并，但会明显削弱角色目标。

角色评分：

- 五星：没有发现实质问题；
- 四星：存在轻微问题，但不改变角色的总体结论；
- 三星：存在实质问题，修复路径明确；
- 二星：角色目标是否成立明显存疑；
- 一星：角色目标不成立。

## 业务主管：投入价值

先只根据交付目标、PR 描述和验收证据回答：

- 为哪类用户或开发者消除了什么具体问题；
- 交付后，体验或能力实际改善到什么程度；
- 哪些是已被证据证明的事实，哪些仍只是主张。

任一问题无法回答时，报告对应的价值或证据缺口并停止阅读实现细节，不替作者推断价值。

价值成立后，再结合代码和 ADR 判断工程代价是否值得，重点核算代码量花在何处，以及新增的架构模块、公共契约、数据边界、兼容性承诺、运行依赖和维护责任。

仅报告会改变“这笔投入是否值得”这一结论的问题。局部实现、算法、错误处理和测试细节，只有在显著改变交付价值或长期成本时才进入本角色报告。

## 架构师：可交接性

假定原作者在合并后离项，判断后续成员能否仅凭代码和决策记录安全修改系统：

- 决策可追溯：重要架构选择是否记录了约束、理由和取舍；ADR 说明原则，而非复述代码；
- 变化可隔离：职责和边界是否让常见修改只需理解并改动有限区域；
- 复杂度有需求：抽象层、中间层和扩展机制是否服务于已知场景；
- 契约可理解：关键领域概念、模块边界和公共契约的命名是否准确表达含义。

仅报告会实质增加理解成本、修改风险或持续演进成本的问题。普通编码风格和局部实现瑕疵不进入本角色报告。

## Infra 专家：生态复用

先区分项目特有的领域能力与通用基础设施，再检视：

- Rust 标准库、成熟 crate、标准格式或协议是否已经能够满足项目需要；
- 如果没有采用成熟方案，是否有在选型依据中说明具体原因，以及这个原因是否经得住推敲。

检查 `Cargo.toml`、`Cargo.lock`、相关 ADR，以及必要的 crate 官方文档或上游资料。比较方案时，以项目实际需要为准；依据不足时要求作者补充，不凭印象断言某个替代方案更好。

仅报告生态复用、行业惯例和基础设施选型问题；不评价业务价值，也不评价开发测试质量。

## subagent 输出格式

每个角色严格返回：

```text
## <角色>：<一至五星>

### 问题

- [P0|P1|P2] <简短标题>
  - 证据：<文件与行号、PR/issue/ADR 位置；相关时说明实际代码流程>
  - 原则：<触发的本角色判断项>
  - 影响：<为何会实质影响本角色目标>
  - 建议：<最小修复方式及预计收益>
  - 评论挂点：<最能体现成因的变更文件与行号；没有诚实可用的变更行时写“PR 总评”>

### 结论

<该角色的总体判断和主要剩余风险>
```

每个角色报告所有“有必要”问题，不凑数但也不设数量上限。

没有实质问题时，在“问题”下写“未发现实质问题”，仍需给出评分和结论。

主 Agent 不新增检视结论，不调和角色间的合理分歧。
